Задание 2

Подземелье

Текстовая игра: игрок перемещается между комнатами, собирает и использует предметы, разговаривает с персонажами и сражается с противниками в пошаговом бою. Мир — фиксированный, но нетривиальный, описан в JSON как контент; прогресс игрока хранится отдельно, как сохранение.

Суть проекта

Игра запускается в интерактивном режиме — команды вводятся в цикле, а не по одной из командной строки, в отличие от Терравариума. Это не требование написать движок для произвольного неограниченного мира — достаточно фиксированного, но нетривиального: минимум 5 комнат, минимум 5 предметов, минимум 2 противника.

запуск
$ python main.py --new-game
$ python main.py --load save1.json
команды внутри игры
> go north
> look
> inventory
> take sword
> use potion
> talk guard
> attack goblin
> save
> quit

Глаголы можно адаптировать — например, на русском (идти, осмотреться, взять, атаковать). Обязателен набор сценариев ниже, а не конкретные слова.

Что нужно реализовать

  1. Перемещение по миру — комнаты соединены переходами (north/south/east/west или именованные выходы). Несуществующее направление — понятное сообщение, не ошибка.
  2. Осмотр — описание текущей комнаты, видимые предметы и персонажи/противники в ней.
  3. Инвентарь — просмотр текущего инвентаря игрока.
  4. Взять предмет — переносит предмет из комнаты в инвентарь.
  5. Использовать предмет — эффект зависит от типа: зелье лечит, ключ открывает проход, оружие экипируется. Минимум 2 разных типа предметов с разным поведением.
  6. Диалог с NPC — минимум с одним персонажем: текст, подсказка или предмет в ответ.
  7. Бой — пошаговый обмен уроном между игроком и противником. Заканчивается победой (противник исчезает, возможен дроп), поражением (game over или предложение загрузить сохранение) или бегством (по желанию).
  8. Сохранение и загрузка — команда save пишет комнату, HP, инвентарь и факты (побеждённые противники) в JSON; --load восстанавливает состояние.
  9. Условие победы — достижимая финальная цель (дойти до комнаты, победить противника, собрать предмет) с сообщением об окончании игры.
  10. Обработка ошибок — некорректная команда, отсутствующий в инвентаре предмет, атака без противника в комнате — понятное сообщение, без падения программы.

Мир игры — минимум содержимого

Не цепочка комнат, а мир хотя бы с одним разветвлением/выбором пути.

5+
комнат, связанных между собой
5+
предметов, минимум 2 типов
2+
противника с разными HP и уроном
1+
NPC для диалога

Требования к ООП

Все четыре принципа обязательны и должны присутствовать по существу.

Абстракция

Character — абстрактный класс (abc.ABC) с абстрактными attack(target) и is_alive. Рекомендуется (не обязательно) сделать так же Item с абстрактным use(player).

Инкапсуляция

HP и другие характеристики — защищённые атрибуты (_hp), доступ через @property. Сеттер не позволяет уйти в отрицательные значения или превысить максимум.

Наследование

Player, NPC, Enemy наследуются от Character. Минимум 2 подкласса Item с разным поведением use() — например, Potion и Weapon/Key.

Полиморфизм

Боевая система вызывает attacker.attack(defender) одинаково для игрока и любого противника — без isinstance в основной логике. То же для item.use(player) из инвентаря.

Необязательно, но приветствуется: композиция — Inventory как отдельный класс, которым владеет Player; собственные исключения (ItemNotFoundError, RoomNotConnectedError).

Хранение данных

Ключевое архитектурное требование — контент мира и сохранение прогресса это два раздельных JSON-источника. Загрузка мира и работа с сохранением — через отдельные классы/модули (например, WorldLoader и SaveManager), а не смешанный код внутри игрового цикла. Повреждённый или отсутствующий файл — понятное сообщение об ошибке, не traceback.

Нефункциональные требования

  • Python 3.10+.
  • Игра не падает с необработанным исключением при некорректном вводе игрока.
  • Понятные текстовые сообщения — язык на выбор студента, единообразно.
  • README с описанием команд, примером карты мира и инструкцией запуска.
  • Сторонние библиотеки не обязательны — rich/colorama можно по желанию.

Идеи для дополнительных баллов

  • Несколько сохранений (слоты), команда просмотра списка сохранений.
  • Ветвящиеся диалоги с NPC — выбор реплик, влияющих на игру.
  • Простая система уровней/опыта игрока.
  • Разные типы противников с уникальным поведением в бою, не только цифрами.
  • Простые unit-тесты (unittest/pytest) на боевую систему и загрузчик мира.
